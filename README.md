# revert-files

一个 DeepSeek Harness（DSH）插件：**用 Git 快照，把工作区与对话回退到某一轮 Agent 对话开始之前**，并补上 DSH 本身没有的**永久删除会话**。

每轮对话开始时插件会对工作区做一次快照；之后可以整轮回退（工作区 + 对话），也可以只回退某个文件。回退后该轮及其之后的轮次会从模型上下文中消失，聊天里对应的消息也被隐藏 —— 模型不会"记得"已被撤销的内容。

- 宿主半边（Node）：[`index.js`](index.js) —— 快照、恢复、对话回退、会话删除
- 浏览器半边：[`client.js`](client.js) —— 撤回按钮、确认卡片、聊天行隐藏、会话行删除项

## 功能特性

- **每轮自动快照**：`turn/start` 时抓取，并在文件写入意图（`fs/write-intent` 等）上等待快照完成；快照取自工作区，因此 `bash` 造成的改动同样被覆盖。
- **整轮回退**：这一轮修改/删除的文件写回原文，新建的文件被删除。
- **单文件回退**：与整轮同一套快照与恢复逻辑，只作用于一个仓库相对路径。
- **对话回退 + 聊天行隐藏**：该轮起点之后的节点被一个空 `user/message` 表层替换遮蔽，客户端按检查点携带的轮次范围隐藏聊天气泡。
- **四类入口**：用户消息行按钮、变更审查（deliverables）文件动作、`/revert` 命令、`revert_files` 工具。
- **先预览后执行**：按钮先取 `--plan`，确认卡片显示宿主返回的真实文件清单；宿主拒绝预览时卡片只给"关闭"。
- **工具回退走审批**：`revert_files` 的 `revert` 由宿主审批通道确认，没有可应答的审批者时按拒绝处理（fail closed）；`list`/`plan` 不改动任何东西，不请求审批。
- **不碰用户 Git 状态**：使用 Git 目录下的私有索引，快照固定在 `refs/dsh/revert-files/…`（`git gc` 不回收）；gitignored 路径既不进快照，也不会被恢复删除。
- **永久删除会话**：会话行菜单里的"删除会话（永久）"清除会话目录（日志 + 写租约）、`session_projcache` 投影检查点与工作区注册表记录，并通知所有客户端摘掉该行；删除前同样先预览。

## 环境要求

- DSH，并装配 `@deepseek-ai/dsh-client-ui-chat`、`@deepseek-ai/dsh-client-ui-deliverables`、`@deepseek-ai/dsh-client-ui-context-menu`（`package.json` 的 `dsh.client.inject`）。
- 宿主侧需要 `fs`、`tools`、`commands` 三个服务；删除会话另需 `sessionPersistence`、`workspaceRegistry`、`storage`（按需 `ctx.get`，缺失时只有删除不可用，回退不受影响）。
- 会话工作目录必须是 **Git 仓库**，且 `git` 在 `PATH` 上。
- 只有 `git add -A` 能看到的路径参与快照，因此 `.gitignore` 命中的文件不参与回退。

## 安装与启用

插件包通过 profile 的 `package.json` 以 `link:` 方式接入并加入 bundle 列表：

```jsonc
// ~/.dsh/profiles/<profile>/package.json
{
  "dependencies": {
    "@local/revert-files": "link:/absolute/path/to/dsh-revert-files"
  },
  "dsh": {
    "profile": {
      "bundles": [
        // …其他 bundle
        "@local/revert-files"
      ]
    }
  }
}
```

包内 [`cordis.patch.yml`](cordis.patch.yml) 负责把插件插入组合树：

```yaml
- insert:
    - id: revert-files
      name: '@local/revert-files'
```

改完后重启 DSH（`index.js` 由宿主进程加载；`client.js` 由 `/plugins` 路由按文件修订号提供，宿主重新扫描后刷新页面即可生效）。

## 使用方式

### 1. 用户消息行上的「撤回」

每条用户消息右侧的操作条里多出一个「撤回」按钮。点击**不会**直接执行：客户端先发 `/revert --turn N --plan`，把文件清单渲染成确认卡片，点「确认撤回」才执行 `/revert --turn N`。

### 2. 变更审查里的单文件「撤回」

deliverables 变更审查面板中，每个文件动作区多出一个「撤回」，只把该文件恢复到它所属轮次开始前的内容，转发为 `/revert --seq <事件序号> --index <文件下标>`。

### 3. `/revert` 命令

```
/revert [--list] [--plan] [--turn N] [--seq N --index N] [--undo N]
```

| 参数 | 说明 |
| --- | --- |
| `--list` | 列出有快照的轮次（最多 30 条）及每轮相对当前工作区的改动统计 |
| `--plan` / `--dry-run` | 只预览，不改动任何东西 |
| `--turn N` | 回退第 N 轮；省略时用当前轮，没有当前轮则用最新有快照的轮 |
| `--seq N --index N` | 只回退一个文件：`N` 是该文件变更记录所在事件的 seq，`index` 是文件在该记录里的下标 |
| `--undo N` | 回到某个反悔点：`N` 是上一次回退在报告里给出的令牌。只恢复文件，不碰对话；不能与 `--turn` / `--seq` 同用 |

参数不合法（`--turn abc`、`--turn 0`、只给 `--seq` 不给 `--index`、未知参数等）会直接报错，**不会**回落到当前轮 —— 回退不可逆，拼错参数不该产生副作用。`revert_files` 工具对 `turn` 采用同一套校验。

反悔点是在动工作区**之前**把当时的完整工作区固定成一棵 tree，因此它保存的正是这次回退覆盖掉的内容。每执行一次回退（包括 `--undo` 本身）都会落下新的反悔点，可以来回走；但它只恢复文件，**对话回退无法撤销**。

### 4. `revert_files` 工具

同一操作也暴露给模型：

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `action` | `list` \| `plan` \| `revert` | 列出快照 / 预览某一轮的改动 / 执行回退 |
| `turn` | integer，可选 | 目标轮次；省略时用最新轮 |

返回 `{ text }`（面向模型的可读报告）。`action: "revert"` 先请求用户审批；用户拒绝、审批通道缺席或调用没有 Agent 时都以普通工具错误结束，文件不会被改动。

### 5. 侧边栏会话行上的「删除会话（永久）」

在左侧会话列表对任意一行打开 `…` 菜单（或右键），最后一项就是它。点击后先弹出确认卡片（会话目录与日志体积等），确认按钮是危险样式；宿主判定不能删时预览直接失败，卡片只留「关闭」。

失败文案会指出具体哪一环出了问题：

| 文案 | 含义 | 怎么办 |
| --- | --- | --- |
| 宿主还没有装配删除命令 | 运行中的宿主里没有 `delete-session` | 重启 DSH |
| 删除命令没能送进承载会话 | 承载会话没有可用的 Agent，或命令通道拒绝受理 | 先打开任意一个已有对话的会话 |
| 宿主接受了删除命令，但没有回报检查结果 | 命令已被受理，只是 2.5s 内没等到回报 | 稍后重试 |
| 该会话仍在本次 DSH 运行中驻留 | 目标会话被装载过，写句柄还压在日志上 | 重启 DSH 后再删 |
| 会话目录的命名与存储布局不符 | 持久层改了目录命名，插件无法验证待删目录 | 不要删；确认没有第二个 DSH 实例或新版布局后再处理 |

删除由宿主执行，也可以直接敲命令：

```bash
/delete-session --id session-359b9b36-… --plan   # 只看会删什么
/delete-session --id session-359b9b36-…          # 真删（不可恢复）
```

这两条命令**不会在 Chat 里留下卡片**：插件用 `conversation.chat.commandview` 这个按命令名索引的座位认领 `delete-session` 并渲染空内容，否则每点一次菜单就会堆一张通用指令卡。需要看报告时请从会话行菜单走确认卡片。

## 限制与取舍

- **日志只追加，对话不会被物理删除**：回退只把内容移出模型历史并隐藏聊天行，原始事件仍在会话日志里 —— 这也是"对话回退无法撤销"的原因。
- **需要 Git 仓库**：不是 Git 仓库时只有文件追踪不可用，错误以中文可读文案返回。
- **Gitignored 路径不参与**：这一轮新建的、被 `.gitignore` 命中的文件（如 `dist/`）回退后仍留在工作区，需要自行清理。
- **仓库外的文件无法回退**：审查面板里可能出现会话工作目录之外、甚至仓库之外的文件（`~/…`、临时目录），单文件回退会明确说明「该文件不在当前 Git 仓库内」。
- **作用域是整个仓库**：快照与恢复都跑在 `rev-parse --show-toplevel` 的仓库根上；会话 cwd 位于大型 monorepo 子目录时，一次回退会影响整个仓库。
- **会话运行中只恢复文件**：有正在执行的回合时不回退对话（避免与进行中的请求竞争），报告里会说明。
- **回退是破坏性的**：会覆盖该轮之后的所有改动，只应在用户明确要求时使用。
- **换过工作目录后，旧轮次在新仓库里回退不了**：快照 ref 挂在各自仓库里，会明确报告"没有可用的快照"。在**同一个**仓库内换到子目录不影响快照。
- **工具回退需要审批**：`/revert` 命令与两个按钮走各自的确认卡片，不经过审批服务。
- **嵌套仓库只记 gitlink**：子目录里带 `.git` 的仓库被记成 commit sha，内容不进快照；其 HEAD 未提交时 `git add` 会失败，该轮快照缺失并记一次警告。
- **不是字节级快照**：内容经 Git 的 `.gitattributes` 过滤器往返；Git LFS 之类过滤器下快照里存的是指针文本，离线还原可能拿不回真实内容。
- **单次回退最多隐藏 1000 轮**：`MAX_HIDDEN_TURNS` 是两端的防跑飞上限；超出上限的更晚轮次在聊天里仍会显示（模型历史已不含它们）。
- **快照 ref 只增不删**：每轮一个 ref，每次回退再落一个 `undo-` ref，插件不回收；`session/disposed` 只清理私有索引文件（best-effort）。
- **宿主侧仍在用已废弃的同步 API**：`session.eventAt` / `session.snapshotEvents`；Harness 移除它们时这里需要改。
- **客户端隐藏依赖隐式 DOM 契约**：`client.js` 靠 `[data-conversation-session]` 与 `[data-chat-turn]` 定位聊天行，上游改名会让隐藏静默失效（工作区回退与模型历史不受影响）。

### 会话删除的边界

- **删不了"本次运行中打开过"的会话**：DSH 一旦装载某个会话，写句柄就压在日志上直到进程退出，此时删文件只会在下一次 flush 时被重建。这是宿主设计，不是插件的保守选择 —— 请**重启 DSH 后**再删。
- **删除需要另一个会话承载命令**：命令通道必须发进一个活着的会话，且不能是目标本身；列表里只有目标时会要求先打开任意一个其它会话。
- **只删会话自己的数据**：会话引用的图片附件（`~/.dsh/cache/attachments/…`）内容寻址、跨会话共享，不随会话删除。
- **多进程不设防**：`session.lock` 上是 POSIX `flock`，纯 JS 探测不到另一个 DSH 进程；请勿让两个实例共用同一个 `~/.dsh` 并对同一会话执行删除。
- **`api-session/removed` 是出厂事件**：上游改名后删除本身仍生效（文件已删），只是侧边栏要等下一次基线刷新才更新。
- **注册表内存索引滞后到重启**：删除后本进程内 `sessionKnown()` 可能仍认这个 id；落盘状态已清净，重启后一致。

## 开发与测试

```
.
├── index.js / client.js     # 宿主半边 / 浏览器半边
├── cordis.patch.yml         # 组合树插入声明
├── locale/zh.json           # 插件元信息（中文）
└── test/                    # client.test.mjs（DOM/React 桩）、host.test.mjs（临时 Git 仓库）
```

```bash
npm test          # = node test/client.test.mjs && node test/host.test.mjs
```

- `test/client.test.mjs` 用最小 DOM + React 桩验证按钮落位、确认卡片流程、回退轮次隐藏，以及会话删除的菜单项、承载会话选择、拒绝路径与命令卡认领。
- `test/host.test.mjs` 在临时目录建真 Git 仓库并驱动 `apply()`，断言回退检查点形状、跨仓库切换、单文件重命名回退、反悔令牌语义、审批门与会话删除的清理范围。

修改代码后：宿主半边需重启 DSH，浏览器半边刷新页面即可。
