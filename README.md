# revert-files

一个 DeepSeek Harness（DSH）插件：**用 Git 快照，把工作区与对话回退到某一轮 Agent 对话开始之前**，顺带补上 DSH 本身没有的**永久删除会话**。

每轮对话开始时，插件对工作区做一次快照。之后你可以整轮回退（工作区 + 对话），也可以只回退某一个文件。回退后，该轮及其之后的轮次会从模型上下文中消失，聊天里对应的消息也会被隐藏——模型不会「记得」已被撤销的内容。

| 半边 | 文件 | 负责 |
| --- | --- | --- |
| 宿主 | [`index.js`](index.js) | 快照、恢复、对话回退、`/revert` 与 `revert_files` 工具、会话删除 |
| 浏览器 | [`client.js`](client.js) | 消息行「撤回」按钮、确认卡片、聊天行隐藏、会话行删除菜单项 |

> 撤销的是**整轮**：该轮改过的文件写回原文，该轮新建的文件被删除，该轮删掉的文件被还原。它不是「撤销上一步编辑」。

---

## 功能一览

- **每轮自动快照**：`turn/start` 时抓取；文件写入意图（`fs/write-intent` / `fs/edit-intent` / `fs/delete-intent`）会等快照落盘后才放行。快照取自**工作区**而不是「插件的写入意图」，所以 `bash` 命令造成的改动同样被覆盖。
- **整轮回退**：文件恢复 + 对话回滚，一次操作。
- **单文件回退**：与整轮同一套快照与恢复逻辑，只作用于一个仓库相对路径；重命名会正确还原成「旧路径写回 + 新路径删除」。
- **对话回退**：该轮起点之后的表层节点被一次空 `user/message` 替换遮蔽，模型历史里不再有这些内容；客户端按检查点携带的轮次范围隐藏聊天气泡。
- **四类入口**：用户消息行按钮、变更审查（deliverables）文件动作、`/revert` 命令、`revert_files` 工具。
- **先预览，后执行**：按钮先取 `--plan`，确认卡片显示宿主返回的真实文件清单。**只有宿主真正回报了计划才会出现可点的确认按钮**——撤回不可逆，不能在没有预览的情况下执行。
- **工具回退走审批**：`revert_files` 的 `revert` 由工具层路由到 `ctx.approval`，没有可应答的审批者时按拒绝处理（fail closed）；`list` / `plan` 不改动任何东西，不请求审批。
- **反悔点**：每次回退在动工作区**之前**把当时的完整工作区固定成一棵 tree，报告里给出令牌，`/revert --undo <令牌>` 可以走回去（只走文件，对话回滚无法撤销）。
- **不碰用户 Git 状态**：所有 Git 调用都用 Git 目录下的**私有索引**，用户真实的索引、HEAD 与分支不会被读写；快照固定在 `refs/dsh/revert-files/…`，`git gc` 剪不到。
- **连带删除会点名**：极少数情况下恢复会不得不删掉被 Git 忽略的文件（见[限制](#限制与取舍)）。预览与执行报告都会逐个列出它们。
- **永久删除会话**：清会话目录（日志 + 写租约）、投影缓存与工作区注册表记录；会话仍驻留在本次运行中时，可 `--force` 先卸载再删，不必重启 DSH。

## 工作原理

### 快照

```
turn/start ──► git add -A（私有索引）──► git write-tree ──► update-ref refs/dsh/revert-files/<会话>/turn-N
```

- 私有索引落在 Git 目录内：`<gitDir>/dsh-revert-files.index.<会话标识>`，用户的 `.git/index` 全程未被触碰。
- `update-ref` 用全零旧值做一次 compare-and-swap：ref 已存在时 Git 会拒绝覆盖，于是并发的第二个快照只能接受先到者。
- 一轮的前像一旦固定就是**不可变**的。重新解析仓库坐标（工作目录在同一个仓库内移动、会话被重新打开、两次调用重叠）不会用一个更晚的状态替换它——那会把「这一轮之前」悄悄变成「这一轮的一部分写入之后」。

### 恢复

```
git read-tree --reset -u <tree>（私有索引）
```

工作区精确回到创建该 tree 时持有的那些字节：该轮删除的文件回来，该轮新建的文件消失。被 Git 忽略的路径在两个方向都在快照之外——正常情况下恢复不捕获、也不删除它们。

### 对话回滚

日志是**仅追加**的，所以对话不会被物理删除。插件追加一次空的 `user/message` 表层替换，遮蔽从该轮第一条消息到表层末尾的每个表层节点：

- 模型看不到那一轮及其之后的任何内容；
- 空内容不产生文本，provider 适配器会丢掉空节点，因此对模型不可见；
- 出厂 Chat 只渲染追加来源的节点，所以该检查点对聊天界面也不可见；
- 该替换的消息 `source` 携带被隐藏的轮次范围（`{kind: 'revert-files', from, to}`），浏览器半边正是据此隐藏聊天记录行。

为什么只能是 `user/message`：当前会话格式要求每个 `system/message`、`developer/message` 与 `assistant/attempt` 都与已打开的轮次和步匹配，而回退总是在会话空闲时运行——此时只有 `user/message` 可以替换一段表层。

### 反悔点

回退前用 `git write-tree` 把「当前」固定成 `refs/dsh/revert-files/<会话>/undo-<令牌>`。它与 `turn-…` 分开命名，因此绝不会被当成某一轮的前像，也不会挡住下一轮自己的快照。令牌单调递增（`Math.max(Date.now(), 上一次 + 1)`），同一毫秒内的两次回退不会撞车。

### 仓库切换

会话的工作目录可能在会话中途改变（`working_directory` 是面向模型的工具）。`working-directory/change` 事件会丢弃该会话所有以仓库为作用域的缓存——解析出的根、已固定的树、进行中的快照——因为它们都属于它刚刚离开的那个检出。在新仓库里恢复旧仓库的树，要么因陌生对象失败，要么更糟：重写错误的检出。

## 关于范围：这个包里有两个功能

**回退**（Git 快照 → 工作区 + 对话）与**删除会话**（清会话产物）是两件独立的事，只是恰好住在同一个包里，共用同一套「命令 → 预览卡片 → 确认」的管线。

| | 回退 | 删除会话 |
| --- | --- | --- |
| 入口 | 消息行按钮、审查文件动作、`/revert`、`revert_files` 工具 | 会话行菜单、`/delete-session` |
| 需要的宿主服务 | `fs`、`tools`、`commands`、`subprocess`、`sessions`、`workspaceChanges` | 另加 `sessionPersistence`、`workspaceRegistry`、`storage` |
| 碰 Git | 是 | 否 |
| 碰会话日志 | 只追加检查点 | 从不打开 |

所以**任一侧坏掉都不影响另一侧**：`delete-session` 的服务缺失时只有它会回答「宿主还没有装配删除命令」，回退照常工作；反之亦然。

之所以没有拆成两个包：删除会话依赖若干**未公开的宿主内部形状**——`sessionPersistence.root`、`storage.backend.get(name).root`、以及 `Symbol.for('cordis.effect')` 上的 `agentLoop.lifecycle(<id>)` 标签。这些字段变了只会让「删除」降级，因此把它们和成熟稳定的回退逻辑放在一起，比单独一个处处是版本断言的包更容易维护。真要切开，按上表切即可：两条路径之间没有需要拆解的耦合。

## 环境要求

- **DSH**，并装配 `@deepseek-ai/dsh-client-ui-chat`、`@deepseek-ai/dsh-client-ui-deliverables`、`@deepseek-ai/dsh-client-ui-context-menu`（见 `package.json` 的 `dsh.client.inject`）。
- 宿主侧**必须**注入 `fs`、`tools`、`commands` 三个服务（`index.js` 的 `inject`）。其余服务都按需 `ctx.get`，缺失时只有对应功能降级：
  - `subprocess`、`sessions`——没有它们回退完全不可用（跑不了 `git`，也定位不到会话）；
  - `workingDirectory`、`sandbox`、`sandboxPolicy`、`agents`——可缺失；缺失时回退到会话 header 的 cwd，`git` 不在沙箱里执行；
  - `workspaceChanges`——只在「变更审查里单文件回退」时需要：没有它 `--seq/--index` 会报告「找不到该文件所属的变更记录」，整轮回退与 `/revert --turn N` 不受影响；
  - `sessionPersistence`、`workspaceRegistry`、`storage`——只在删除会话时需要。
- 会话工作目录必须是 **Git 仓库**，`git` 在 `PATH` 上。插件用到 `--no-optional-locks`（需 Git 2.15+）与 `GIT_NO_LAZY_FETCH`（需 Git 2.45+；更早的 Git 会忽略这个变量，只是缺了「不要懒抓取」这层保险）。
- 只有 `git add -A` 能看到的路径参与快照，因此 `.gitignore` 命中的文件不参与回退。
- 界面文案随包提供中文与英文两套（`locale/zh.json`、`locale/en.json` 提供插件元信息；控件词条内联在 `client.js`）。缺失的语言按「当前语言 → en → 裸 key」回退。

## 安装与启用

通过 profile 的 `package.json` 以 `link:` 方式接入，并加入 bundle 列表：

```jsonc
// ~/.dsh/profiles/<profile>/package.json
{
  "dependencies": {
    "@local/revert-files": "link:/absolute/path/to/dsh-revert-files"
  },
  "dsh": {
    "profile": {
      "bundles": [
        // …其他 bundle
        "@local/revert-files"
      ]
    }
  }
}
```

包内的 [`cordis.patch.yml`](cordis.patch.yml) 负责把它插入组合树：

```yaml
- insert:
    - id: revert-files
      name: '@local/revert-files'
```

改完**重启 DSH**（`index.js` 由宿主进程加载）；`client.js` 由 `/plugins` 路由按文件修订号提供，刷新页面即可生效。日常开发时：宿主半边改动 → 重启 DSH，浏览器半边改动 → 刷新页面。

## 使用方式

### 1. 用户消息行上的「撤回」

每条用户消息的操作条里多出一个「撤回」按钮。点击**不会**直接执行：

1. 客户端发 `/revert --turn N --plan`，向宿主索取预览；
2. 确认卡片列出将被回退的文件（以及会被连带删除的忽略文件）；
3. 点「确认撤回」才执行 `/revert --turn N`。

轮次号不在按钮的 props 里——座位的所属者只交出持久化的消息 `source`，所以客户端拿它与该行构建的用户节点做匹配，从 Chat 快照里反查出 `location.turn.turn`。解析不出轮次的行什么都不渲染。

### 2. 变更审查里的单文件「撤回」

deliverables 变更审查面板中，每个文件动作区多出一个「撤回」，只把该文件恢复到它所属轮次开始前的内容，转发为：

```
/revert --seq <事件序号> --index <文件下标>
```

坐标来自该面板自己的路由 `changes.open?sessionId=…&seq=…&index=…`。宿主按 `/^(0|[1-9][0-9]*)$/` 校验；`1e3`、`0x10`、`+5` 一律拒绝——`Number()` 会把它们变成另一个数字，于是撤回的就是另一个文件。

### 3. `/revert` 命令

```
/revert [--list] [--plan] [--turn N] [--seq N --index N] [--undo N]
```

| 参数 | 说明 |
| --- | --- |
| `--list` | 列出有快照的轮次（最多 30 条）及每轮相对**当前**工作区的改动统计 |
| `--plan` / `--dry-run` | 只预览，不改动任何东西 |
| `--turn N` | 回退第 N 轮；省略时用当前轮，没有当前轮则用最新有快照的轮 |
| `--seq N --index N` | 只回退一个文件：`N` 是该文件变更记录所在事件的 seq，`index` 是文件在该记录里的下标（必须同时给出） |
| `--undo N` | 回到某个反悔点，`N` 是上一次回退报告里给出的令牌；只恢复文件，不碰对话；不能与 `--turn` / `--seq` 同用 |

参数不合法（`--turn abc`、`--turn 0`、只给 `--seq` 不给 `--index`、`--undo` 与 `--turn` 同时出现、未知参数等）直接报错，**不会**回落到当前轮——回退不可逆，拼错参数不该产生副作用。

`--list` 的输出形如：

```
仓库 /Users/me/project
第 3 轮 · 4a1c9f2e8b70 — 涉及 2 个文件（1 修改 / 1 新增将删除 / 0 删除将还原）。
第 2 轮 · 77de01bb9c33 — 工作区与快照一致，没有需要恢复的改动。
```

### 4. `revert_files` 工具

同一套规划器与恢复器也暴露给模型：

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `action` | `list` \| `plan` \| `revert` | 列出快照 / 预览某轮改动 / 执行回退 |
| `turn` | integer，可选 | 目标轮次；省略时用最新一轮 |

返回 `{ text }`（面向模型的可读报告）。`action: "revert"` 会先请求用户审批：

- 审批文案点名轮次（`撤回整个工作区与对话（第 N 轮，基于 Git 快照，会覆盖该轮之后的改动）`）；
- 审批通道缺席时失败关闭，拒绝是一次普通的工具错误；
- `turn` 不合法（`0`、小数、字符串）**直接拒绝且不请求审批**——一个拼错的轮次会被 `execute` 拒绝、什么也不改，先弹一次审批只会让用户习惯于不看内容就点同意。

### 5. 侧边栏会话行上的「删除会话（永久）」

在左侧会话列表对任意一行打开 `…` 菜单（或右键），最后一项就是它（排在出厂归档条目之后）。点击后先弹确认卡片（会话目录、日志体积等），确认按钮是危险样式。宿主判定不能删时预览直接失败，卡片只留「关闭」。

会话仍驻留在本次运行中时，普通预览会被拒绝，卡片随即自动改用 `--force` 再问一次：标题变成「从本次运行中卸载并永久删除这个会话？」，确认按钮变成「强制删除」。确认后宿主**先卸载这个会话**（停掉进行中的回合、关闭日志写句柄、把它摘出会话与 Agent 注册表），再删数据——不需要重启 DSH。

命令通道也可以直接用：

```bash
/delete-session --id session-359b9b36-… --plan            # 只看会删什么
/delete-session --id session-359b9b36-… --plan --force    # 看「卸载再删」会做什么
/delete-session --id session-359b9b36-…                   # 真删（不可恢复）
/delete-session --id session-359b9b36-… --force           # 先卸载再删
```

它删掉的东西：会话目录（日志 + 写租约）、投影检查点（`<root>/session_projcache/sessions/<id>.json`，里面存着标题与首个提示词）、以及工作区注册表里的归档、置顶与成员记录，最后广播 `api-session/removed`。**不会**动跨会话共享的附件（`~/.dsh/cache/attachments/…`，内容寻址）。

`/delete-session` **不会在 Chat 里留下卡片**：插件用 `conversation.chat.commandview` 这个按命令名索引的座位认领 `delete-session` 并渲染空内容，否则每点一次菜单就会堆一张通用指令卡。需要看报告时请走会话行菜单的确认卡片。（`/revert` 没有这样做——它本来就是要有可见结果的命令。）

## 报告与失败文案

### 回退

| 文案 | 含义 | 怎么办 |
| --- | --- | --- |
| 宿主还没有装配撤回命令 | 运行中的宿主里没有 `revert` | 重启 DSH |
| 撤回命令没能送进会话 | 没有会话能承载这条命令 | 先打开任意一个已有对话的会话 |
| 宿主没有回报预览 | 命令已被受理，但 2.5 s 内没等到回报 | 稍后重试 |

这三种结局都不会给出可点的确认按钮：没有预览就没有可以照着做的清单，而撤回不可逆。

整轮回退报告里的对话部分有五种：

| 文案 | 含义 |
| --- | --- |
| 已撤回对话内容：第 X–Y 轮… | 对话一起回滚了（这一步无法撤销） |
| 对话内容此前已经撤回。 | 更早的一次回退已经遮蔽了这一段 |
| 无法在对话中定位这一轮，本次只恢复了文件。 | 日志里找不到该轮的 `turn/start` 边界 |
| 会话正在运行，本次只恢复了文件。 | 有进行中的回合，不与它竞争 |
| 对话内容未能撤回：… | 追加检查点时出错，文件已恢复 |

### 删除会话

| 文案 | 含义 | 怎么办 |
| --- | --- | --- |
| 宿主还没有装配删除命令 | 运行中的宿主里没有 `delete-session` | 重启 DSH |
| 承载会话没有接受这条删除命令 | 承载会话没有可用的 Agent，或通道拒绝受理 | 先打开任意一个已有对话的会话 |
| 侧边栏里只有这一个会话 | 删除必须由另一个会话承载命令，而列表里没有第二个 | 先打开任意一个其它会话 |
| 宿主接受了删除命令，但没有回报检查结果 | 命令已被受理，2.5 s 内没等到回报 | 稍后重试 |
| 该会话仍在本次 DSH 运行中驻留 | 目标会话被装载过，写句柄还压在日志上 | 点「强制删除」，或加 `--force` |
| …而且找不到它的生命周期边界 | 宿主版本换了 effect 标签，无法安全卸载 | 重启 DSH 后再删 |
| 没能把这个会话从本次运行中卸载 | 卸载本身失败或超时（10 s） | 重启 DSH 后再删 |
| 会话目录的命名与存储布局不符 | 持久层改了目录命名，无法验证待删目录 | 不要删；确认布局后再处理 |
| 无法验证会话目录是否在会话根内 | 持久层不再暴露会话根 | 重启或升级后再删 |
| 无法定位会话的投影缓存 | 存储后端不再暴露它的根，检查点无法确认 | 重启或升级后再删 |
| 这个会话的 ID 无法安全地传给宿主命令 | 会话 id 含空白或会改变切分/解析的字符 | 不要删；这多半不是宿主生成的 id |

## 限制与取舍

- **日志只追加，对话不会被物理删除**：回退只把内容移出模型历史并隐藏聊天行，原始事件仍在日志里——这也是「对话回退无法撤销」的原因。
- **需要 Git 仓库**：不是 Git 仓库时只有文件追踪不可用，错误以中文可读文案返回。
- **Gitignored 路径不参与**：这一轮新建的、被 `.gitignore` 命中的文件（如 `dist/`）回退后仍留在工作区，需要自行清理。
- **一个例外：被跟踪的文件换成同名目录时，目录里的忽略文件会被删**。恢复要把那个路径写回成**文件**，就得先清掉挡路的**目录**，于是目录内被忽略的内容一并消失——那些字节既不在快照里，也无处可恢复。这类文件会在预览卡片与执行报告中逐个列出（`⚠ 以下被 Git 忽略的文件会一并删除`），**务必在确认前看一眼**。（如果这份清单查不出来，插件会记一条警告，而不是安静地当成「没有」。）
- **稀疏检出只覆盖 cone 内**：仓库启用 `core.sparseCheckout` 时，`git add -A` 只看得到 sparse-checkout 范围内的路径，快照因此只是工作区的一个子集。回退**不会**删掉范围外的文件，但报告会明确说明「只覆盖范围内的文件」，不会声称已完整恢复；范围外的改动不在快照里，也就无从回退。若范围外路径带有未提交的改动，Git 会拒绝建立快照，此时预览与回退会给出一条可照做的说明，而不是 Git 的原文。
- **残留索引锁会被自动清理**：`git` 若在持有私有索引的 `.lock` 时被超时终止（单次调用上限 120 s），锁会留在 Git 目录里，此后该会话每次 `git add` 都以 128 失败。插件识别这种失败、只清理**自己**的私有/临时索引锁（绝不碰用户真实索引的锁）后重试一次；`session/disposed` 也会顺手清掉它。
- **仓库外的文件无法回退**：审查面板里可能出现会话工作目录之外、甚至仓库之外的文件（`~/…`、临时目录），单文件回退会明确说明「该文件不在当前 Git 仓库内」。
- **作用域是整个仓库**：快照与恢复都跑在 `rev-parse --show-toplevel` 的仓库根上；会话 cwd 位于大型 monorepo 子目录时，一次回退会影响整个仓库。
- **快照要扫整个仓库**：每次快照与预览都在仓库根上跑一次 `git add -A`。大型 monorepo 里这是一次全仓扫描，也是 2.5 s 预览超时最容易撞上的地方。
- **会话运行中只恢复文件**：有正在执行的回合时不回退对话（避免与进行中的请求竞争），报告里会说明。「是否在运行」以**日志**为准——`state.running` 只由本进程看到的实时 `turn/start` 置位，所以插件在轮次进行中被加载（HMR，或 agent resume 之后才 `apply()`）时会以为会话空闲；判断因此改为「实时事件**或**日志里还有未配对的 `turn/start`」。
- **一轮的第一条命令是 `bash` 时，前像可能不准**：快照在 `turn/start` 之后异步开始，而「写入前等快照」的屏障只拦文件工具，不拦 shell。一轮的第一条命令如果是 `bash` 且改了文件，而 `git add -A` 还没跑完，那份改动会被算进「轮次之前」，此后回退该轮撤销不了它。文件工具写入不受影响。
- **换过工作目录后，旧轮次在新仓库里回退不了**：快照 ref 挂在各自仓库里，会明确报告「没有可用的快照」。在**同一个**仓库内换到子目录不影响快照。
- **回退是破坏性的**：会覆盖该轮之后的**所有**改动，只应在用户明确要求时使用。工具的 `revert` 因此走审批，两个按钮走各自的确认卡片。
- **单次回退最多隐藏 1000 轮**（`MAX_HIDDEN_TURNS`，两端各有一份）。隐藏范围的另一端取自**对话实际推进到的位置**（日志里出现过的最大轮次，以及已固定的快照），而不是「哪一轮成功落下了快照」——否则中间几轮快照失败之后，回退会把范围报小：模型历史已不含那几轮，聊天里却还显示着。
- **快照 ref 只增不删**：每轮一个 ref，每次回退再落一个 `undo-` ref，插件不回收；`session/disposed` 只清理私有索引文件（best-effort）。
- **嵌套仓库只记 gitlink**：子目录里带 `.git` 的仓库被记成 commit sha，内容不进快照；其 HEAD 未提交时 `git add` 会失败，该轮快照缺失并记一次警告。
- **不是字节级快照**：内容经 Git 的 `.gitattributes` 过滤器往返；Git LFS 之类过滤器下快照里存的是指针文本，离线还原可能拿不回真实内容。
- **继承来的 Git 环境变量一律清掉**：DSH 的子进程基座只过滤敏感名与 `DSH_*`，其余环境变量原样继承。所以每条 `git` 调用都在一份固定环境里运行，按「能改变哪一件事」清空仓库身份（`GIT_DIR`、`GIT_WORK_TREE`、`GIT_NAMESPACE`…）、配置来源（`GIT_CONFIG_GLOBAL`、`GIT_CONFIG_SYSTEM`…）、pathspec 语义（`GIT_GLOB_PATHSPECS`、`GIT_ICASE_PATHSPECS`…）、对象/属性来源（`GIT_OBJECT_DIRECTORY`、`GIT_ATTR_SOURCE`…）以及 `GIT_EXEC_PATH` / `GIT_EXTERNAL_DIFF`。这不只是「结果可能不对」：`GIT_CONFIG_GLOBAL` 指向的文件里只要有一个 `filter.*.smudge`，`checkout-index` / `read-tree -u` 就会执行其中的命令；而继承的 `GIT_GLOB_PATHSPECS` 与插件自己的 `GIT_LITERAL_PATHSPECS` 撞上时，`ls-files` 会直接 `fatal`，单文件回退从此不可用。
- **Git 路径按字面量解析**：单文件回退用 `GIT_LITERAL_PATHSPECS=1`，名字里带 `[`、`]`、`*`、`?` 的文件不会被当成 glob；解析出的仓库相对路径还会再核对一次，确保操作的就是被点名的那一个文件。
- **写意图屏障做成最外层监听器**：`fs/*-intent` 是单槽位瀑布流，不调用 `next()` 的监听器会否决整条链（`dsh-fs-observation-policy` 就是这样做的）。插件用 `prepend` 注册成最外层，因此不受注册顺序影响，最终的新鲜度决定权仍然交回上游。
- **宿主侧依赖两个已废弃的同步 API**：`session.eventAt` / `session.snapshotEvents`。Harness 移除它们时这里需要改。
- **客户端依赖隐式 DOM 契约**：靠 `[data-conversation-session]` 与 `[data-chat-turn]` 定位聊天行来隐藏已回退的轮次；靠 `<hash>_actions` 这个 CSS-module 类名、`data-chat-flow-kind` 行边界属性，以及「操作条是座位元素的直接子节点」这层结构来落位按钮。上游任意一处改名，隐藏或按钮都会安静地失效（工作区回退与模型历史不受影响）。

### 会话删除的边界

- **驻留会话默认拒绝，`--force` 才卸载**：DSH 一旦装载某个会话，写句柄就压在日志上，直接删文件只会在下一次 flush 时被重建。`--force` 先发 `workspace/session-stop` 停掉该会话的工作，再调用宿主里 `agentLoop.lifecycle(<id>)` 那个 effect 的清理器——它自己会取消驱动、等它 idle、排空并关闭写句柄，并把会话与 Agent 摘出注册表。代价是那次卸载是终局的：该会话的 Agent 不会自己回来，下次从列表里打开它时会重新 resume。
- **卸载依赖 effect 标签**：按 `Symbol.for('cordis.effect')` 上的 `agentLoop.lifecycle(<id>)` 标签找生命周期，找不到就拒绝并建议重启，而不是猜着删。
- **删除需要另一个会话承载命令**：命令通道必须发进一个活着的会话，且不能是目标本身。承载者只从「真正的对话行」里挑：**子 Agent 行**（`origin: 'subagent'`）由子 Agent 路由独占，宿主对它直接回 `session/agent-busy`；**空白新会话行**（`blank`）还没有可运行命令的 Agent。这两类被排除在候选之外。
- **路径安全优先于便利**：会话目录必须能在会话根内验证、会话 id 必须能安全地拼进命令行、投影缓存根必须可读——任何一条不满足都**拒绝删除**，而不是猜着递归删。
- **多进程不设防**：`session.lock` 上是 POSIX `flock`，纯 JS 探测不到另一个 DSH 进程。请勿让两个实例共用同一个 `~/.dsh` 并对同一会话执行删除。
- **注册表内存索引滞后到重启**：删除后本进程内 `sessionKnown()` 可能仍认这个 id；落盘状态已清净，重启后一致。

## 开发与测试

```
.
├── index.js                # 宿主半边：快照、恢复、对话回退、两条命令、工具
├── client.js               # 浏览器半边：按钮、确认卡片、行隐藏、会话菜单
├── cordis.patch.yml        # 组合树插入声明
├── locale/en.json, zh.json # 插件元信息（英文 / 中文）
├── icon.svg                # 插件图标
└── test/
    ├── host.test.mjs       # 真 Git 仓库 + 假宿主缝隙
    └── client.test.mjs     # 最小 DOM + React 桩
```

```bash
npm test          # = node test/client.test.mjs && node test/host.test.mjs
```

两套检查都只用 Node 内置模块：零依赖、无构建步骤。`host.test.mjs` 在没有 `git` 时会打印 `SKIP` 并以 0 退出。

**`test/host.test.mjs`** 在临时目录建真 Git 仓库并驱动真正的 `apply()`（一个裸 `subprocess` 缝隙直接跑 `git`，一个假会话提供表层），断言：

- 回退检查点的形状（`user/message`、空 content、携带 `from`/`to`、不写 turn/step 坐标）；
- 跨仓库切换、单文件重命名回退、反悔令牌语义、审批门、`--plan` 预览不改动任何东西；
- 名字里带 glob 元字符的文件必须被**精确**撤回，而不是它的兄弟文件；
- 含 `..` 的会话 id 仍拿得到快照（Git 拒绝含 `..` 的 ref 名）；
- 预置的残留索引锁不得让快照与预览失效，且事后必须已被清掉；
- 被跟踪文件换成同名目录时，预览与执行报告都要点名会被连带删除的忽略文件；
- 稀疏检出下要披露覆盖范围，范围外路径有改动时给出可读说明而不是 Git 原文；
- 继承来的敌意 Git 环境（配置里的 smudge filter、`GIT_GLOB_PATHSPECS`、`GIT_DIR`）不得让快照、回退或单文件路径失效；
- 插件在轮次进行中加载时仍须判定会话在运行、只恢复文件；
- 中间轮次快照失败后，隐藏范围要覆盖到对话实际推进到的最远轮次；
- 会话删除的清理范围、驻留拒绝、强制卸载，以及找不到生命周期边界/布局不符/目录越界时的拒绝。

**`test/client.test.mjs`** 用最小 DOM + React 桩验证按钮落位、确认卡片流程、已回退轮次的隐藏规则，以及会话删除的菜单项、承载会话选择（跳过子 Agent 行与空白新会话行）、拒绝路径、驻留会话改用 `--force` 重预览、命令卡认领。它还守着几条边界：

- 宿主认领了命令却从不回报时，**不得**出现可点的确认按钮；
- 别人的同名命令运行不得被当成本插件的预览（参数必须逐词元相等）；
- StrictMode 的双挂载之后控件仍然可用；
- 审查面板里非法坐标（`1e3`、`0x10`）不渲染任何控件；
- 英文词条必须覆盖中文的每一个 key——运行时按「当前语言 → en → 裸 key」回退，缺一条就会在英文界面里显示成 key。
